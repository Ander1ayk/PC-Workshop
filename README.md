1. Назва мого модуля

3D Game

2. Моя роль у проєкті

Я відповідав за повну розробку ігрової частини проєкту, включаючи створення ігрових механік, систем взаємодії, UI/UX елементів, а також логіку проходження гри. 

3. Що було реалізовано

Було реалізовано:

* систему замовлень від NPC;  
* систему квестів;  
* інвентар гравця;  
* механіку встановлення комплектуючих у ПК;  
* взаємодію з предметами;  
* систему доставки деталей;  
* UI/UX інтерфейси;  
* систему збереження прогресу гри;  
* анімації NPC за допомогою Animator;  
* завантажувальний екран між сценами;  
* звукову систему та налаштування аудіо.  
    
4. Які технології використовувались

У процесі розробки використовувались:

* Unity;  
* C\#;  
* Blender;  
* JSON для збереження прогресу;  
* PlayerPrefs для збереження аудіо налаштувань.  
    
5. Як працює моя частина  

Гравець запускає гру та може почати нове проходження або продовжити вже існуюче. Під час гри NPC створюють замовлення на збірку ПК. Гравець купує необхідні комплектуючі, встановлює їх у корпус ПК та завершує замовлення. Прогрес гри автоматично зберігається у JSON-файл. Backend частина проєкту отримує ці дані та передає їх frontend частині для подальшого використання.

6. Структура файлів або компонентів 

Основними компонентами гри є:

* Collider;  
* Mesh Collider;  
* Character Controller;  
* Rigidbody;  
* Animator.

Основні папки проєкту:

* ScriptableObjects — зберігає характеристики квестів, NPC, ПК та комплектуючих;  
* Scripts — містить усі скрипти гри, розподілені по тематичних підпапках;  
* Scenes — сцени меню та ігрового процесу;  
* Prefabs — готові ігрові об’єкти;  
* UI — елементи інтерфейсу користувача.  
7. Як запустити або перевірити мою частину   
   Для запуску гри необхідно:  
1) Відкрити проєкт у Unity.  
2) Запустити головну сцену.  
3) Натиснути кнопку New Game або Continue.  
4) Під час проходження перевіряються:  
   1. система квестів;  
   2. взаємодія з предметами;  
   3. встановлення деталей у ПК;  
   4. система збереження прогресу.  
8. З чим моя частина взаємодіє 

Ігрова частина взаємодіє з backend частиною проєкту через систему збереження прогресу.

Backend:

* отримує JSON-файли з даними гри;  
* зберігає інформацію про прогрес;  
* передає необхідні дані frontend частині.

Frontend:

відображає отриману інформацію користувачу.

9. Проблеми та рішення 

Основною проблемою була початкова система встановлення деталей у ПК. Спочатку гравець мав обертати корпус ПК та наводити приціл на місце встановлення деталей, що було незручно та неінтуїтивно.

Для вирішення цієї проблеми було реалізовано нову систему взаємодії:

* корпус ПК переміщується перед камерою;  
* взаємодія відбувається за допомогою курсора;  
* встановлення деталей стало швидшим та зручнішим для користувача.  
10.  Що можна покращити в майбутньому

У майбутньому можна:

* покращити систему квестів;  
* розширити механіку доставки деталей;  
* додати систему пакування готового ПК перед відправкою замовнику;  
* реалізувати більше типів комплектуючих та замовлень;  
* покращити UI/UX інтерфейси гри.
